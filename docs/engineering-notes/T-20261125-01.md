## Requirement
Owner directive 2026-11-25: make the Muse ↔ Claude operation permanent (no Nov 27 end), fix the stalled communication,
add recovery for restarts, missed runs, connectivity failures and stalled tasks, with no duplicate workers and no
uncontrolled API use.

## Root cause
1. **No worker for the harness.** Since 2026-11-24, Muse assigned work with `tasks add` to
   "Pilot Harness (Claude Code PC2)". That name is the interactive Claude Code session on PC2, which runs only when the
   owner opens a chat (Crosswalk showed it "checks about every 21 hours"). The cloud engineer routine only handles
   template posts for "CC Engineer" in this repo, and the wake poller reads posts (not task rows) and deliberately skips
   PeptideFacts/PAYMTS/MM. Result: `vc8a2c`, `gady5e`, `vqgo5t`, `ktleg9` sat 15–20 h with no ACK. Nothing was broken:
   poller Ready with 0 missed runs, routines enabled, last runs SUCCEEDED, `poller.log` 120 NOTHING / 78 OUT_OF_WINDOW.
2. **Latent expiry.** Engineer cron `5 0-3,13-23 20-27 11 *`, verifier cron `50 23 20-27 11 *` plus a prompt guard
   ("after 2026-11-27 … PILOT_ENDED"), poller `pilotEnd: '2026-11-27'`, Task Scheduler `EndBoundary 2026-11-28`.
   Everything would have stopped after Nov 27.

### PC2 worker (`tools/pc2-worker`)
- Pre-check with the existing read-only, museclaudepilot-only Crosswalk key (`peek`): zero LLM cost when idle.
- Caps: 08:05–22:05 ET; ≤6 runs per Eastern day; ≥20 min between runs; one task per run; a task is retried at most
  every 6 h and at most 3 times; run killed after 60 min; `--max-budget-usd 8` per run.
- No duplicates: Task Scheduler `IgnoreNew` + atomic lock directory held for the whole run (stale after 70 min);
  attempt recorded before the run starts, so a crash never causes a rapid re-run.
- Safety: `--permission-mode auto` (the owner's own rules and classifier apply; nothing bypassed; anything needing a
  prompt is denied); executable spawned without a shell; the run is given only the task id, never board text; the
  standing instructions live outside this public repo (`%LOCALAPPDATA%\muse-ops-worker\worker-prompt.md`, copy in the
  git-excluded `ops/`). Pause: create `%LOCALAPPDATA%\muse-ops-worker\PAUSE`.

## Decisions and reasoning
- Config override on PC2 first, code change via PR second: the live fix did not need to wait for review.
- Verifier no longer posts for the owner: owner rule (Nov 22/24/25) is that Muse's daily report is the only owner
  channel; the verifier reports to the harness and Muse folds it in.
- Worker uses the read-only poller key for its pre-check instead of a new credential (no credential changes).
- Worker runs only with an open harness task, so idle cost is zero; caps bound the worst case to 6 runs/day.

## Rollback
- Routines: RemoteTrigger `update` with the old crons (above) or `{"enabled": false}`.
- Poller: delete `config.json`; `install-task.ps1` from the previous commit restores the old EndBoundary.
- Worker: `Unregister-ScheduledTask MuseOps-PC2Worker -Confirm:$false`, or create the PAUSE file.

## Lessons learned
- An assignee name on the board is not a worker. Every name Muse can assign to must map to something that runs on
  its own; the verifier's HEARTBEAT check now surfaces any name that doesn't.
- Pilot end dates were spread over 5 places (2 crons, 1 prompt, 1 code default, 1 scheduler boundary). Keep any
  future end date in one config value.
