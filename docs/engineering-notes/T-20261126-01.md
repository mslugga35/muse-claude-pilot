## Problem
The board saw no PC2 activity on 2026-11-26 while 7 harness tasks waited (hs4egt, tvw90p, mho3zd, p9tc1v, uahtj3,
ysg1qa, g1p576). PC2 was up and the worker ran every 10 minutes all day (`worker.log`:
`"ALL_ATTEMPTED_RECENTLY","open":2`).

## Root cause
`harnessTasks()` accepts a task only if its `via` label exactly matches `trustedVia` (`muse`, `owner`, `mpmmorales`,
empty). Since the afternoon of 2026-11-25 Muse creates tasks as **"lilSlug (Muse)"** and the PC1 session as
**"Claude"**. Both are agents of the owner's own account (`by: you`), but neither label matched, so their tasks were
dropped with no log line. The two tasks still visible (vc8a2c, ci9uw9) were blocked / at their retry limit, so the
worker correctly idled.

## Change
| File | Change |
|---|---|
| `tools/pc2-worker/lib.js` | `trustedVia` adds the exact labels `lilslug (muse)` and `claude`; new `refusedTasks()` lists open tasks addressed to the harness that the trust filter refuses |
| `tools/pc2-worker/worker.js` | every CHECK log line carries `refused: [{id, by, via}]` when any harness task is refused, so a refusal is never silent |
| `tools/pc2-worker/test/worker.test.js` | test: lilSlug (Muse) and Claude tasks are worked, Grok Bot and other accounts refused and logged (falsifier: removing the two labels fails it) |

Still exact-match and still owner-account only (`trustedBy: ['you']`); config cannot change either.
