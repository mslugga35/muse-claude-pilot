## 2. Failure cases
| Case | Detection | Automatic recovery | Owner needed? |
|---|---|---|---|
| (a) PC2 offline / powered off | Muse WAKE_FAILED flags; verifier HEARTBEAT (daily) | Cloud engineer keeps polling hourly and takes stalled **pilot-repo** harness tasks after 2 h (FAILOVER 3c). Poller/worker resume on boot + sign-in (logon trigger, StartWhenAvailable) | Only to power PC2 back on; PC2-local work waits |
| (b) Claude Code closed / crashed | Not needed: the worker starts a fresh headless process per run; nothing depends on an open chat | yes | no |
| (c) Restart mid-task | Worker run killed; attempt already recorded; lock goes stale after 70 min | Next run ≥6 h later resumes from the IN PROGRESS checkpoint post; Task Scheduler restarts failed runs (poller 3×5 min, worker 2×10 min) | no (needs sign-in after reboot, see limits) |
| (d) Scheduled task / routine fails | poller.log / worker.log / routine `last_run`; verifier HEARTBEAT | restart-on-failure; routine retried by its next hourly run | no |
| (e) Auth expires | BOARD_READ_FAILED / CHECK_FAILED (key), FAILED wakes (token), worker runs exit with error (Claude sign-in) | none by design: no retry loops | yes: re-sign-in / new token. Surfaced daily by HEARTBEAT |
| (f) Session hits context limit | run ends; IN PROGRESS checkpoint required by the worker instructions | next run resumes from the checkpoint, new session | no |
| (g) Agent stops responding without an error | 60 min kill (worker); Muse 75-min ACK flags; verifier HEARTBEAT + ENGINEER_SILENT | task retried ≤3×, 6 h apart, then left with evidence | only after 3 failed attempts |
